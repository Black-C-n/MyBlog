# 01 项目导读

## 一、先理解整体分层

一次浏览器请求大致经过下面这条链路：

```text
浏览器
  ↓ HTTP 请求
Controller（接收参数、选择页面）
  ↓ 调用业务方法
Service（业务规则、事务）
  ↓ 查询或保存
Repository（JPA 数据访问）
  ↓ SQL
MySQL
  ↑ 查询结果
Entity（数据库记录对应的 Java 对象）
  ↑ Model 数据
Thymeleaf 模板
  ↓ HTML
浏览器
```

每层只负责一件事：

- Controller 不直接写 SQL；
- Repository 不负责判断“两次密码是否一致”；
- Entity 不决定跳转到哪个页面；
- Thymeleaf 不负责保存数据库。

这就是面试中常说的“分层”和“职责单一”。

## 二、目录作用

```text
src/main/java/com/example/myblog
├─ config       配置、拦截器、公共模板数据
├─ controller   URL 和请求处理
├─ entity       数据库表对应的 Java 类
├─ form         表单接收对象与校验规则
├─ repository   数据库查询接口
├─ service      业务逻辑和事务
└─ util         Django 密码兼容工具

src/main/resources
├─ static       CSS、JavaScript、内置博客图片、Django Admin、CKEditor
├─ templates    Thymeleaf 页面
└─ application.properties

storage/media   后台运行时新上传的图片
```

浏览器访问 `/media/**` 时，Spring 会先寻找 `storage/media` 中的新上传图片，再寻找 `static/media` 中随程序打包的原始图片。两处都在 Java 项目内，不依赖原 Python 工程。

## 三、用登录流程学习

### 1. 浏览器提交

`user.html` 的表单 POST 到 `/user/login.html`，字段名是 `username` 和 `password`。

### 2. Controller 接收

`AccountController.login()` 用 `@RequestParam` 接收两个字段，然后调用：

```java
userService.authenticate(username, password)
```

Controller 不知道 PBKDF2 的具体计算细节。

### 3. Service 处理

`UserService.authenticate()`：

1. 按用户名查用户；
2. 判断用户是否启用；
3. 调用 `DjangoPasswordUtil.matches()` 校验密码；
4. 更新最后登录时间；
5. 返回登录用户。

### 4. Session 保存登录状态

登录成功后，Controller 把 `MyUser` 放进 `HttpSession`。以后浏览器带着同一个 `JSESSIONID`，后台拦截器就能识别用户。

### 5. 后台拦截

`AdminLoginInterceptor` 在 Controller 之前执行。未登录、未启用或不是 staff 的用户会跳转到登录页。

## 四、用文章详情学习事务

`ArticleService.findDetail()` 被 `@Transactional` 标注。第一次访问详情时：

1. 执行一条 `reading = reading + 1` 更新；
2. 查询文章及标签；
3. 整个过程在一个事务内完成。

Controller 又用 Session 中的 `reading{用户id}{文章id}` 标记避免同一浏览器反复刷新刷阅读量。

## 五、为什么没有用 Spring Security

Spring Security 更适合正式生产项目，但它包含过滤器链、认证对象、密码编码器和授权规则。这个项目先用 Session + Interceptor 把原理显式写出来，更适合基础学习。面试时可以这样回答：

> 当前项目为了学习 MVC 核心流程采用 Session 和拦截器；如果上线，会迁移到 Spring Security，增加 CSRF、防会话固定攻击和更细的权限控制。
