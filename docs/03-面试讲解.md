# 03 面试讲解与常见问答

## 一分钟项目介绍

> 这是一个从 Django 迁移到 Spring Boot 的个人博客项目。我使用 Spring MVC + Thymeleaf 保留服务端渲染方式，使用 Spring Data JPA 直接映射原 Django 的 MySQL 业务表，因此原文章、评论、相册和用户资料都可以复用。登录采用 HttpSession 和拦截器，另外实现了 Django PBKDF2 密码兼容。后台按登录用户隔离文章、标签、评论、相册和留言，并实现完整 CRUD 和文件上传。项目使用 H2 做自动测试，同时用真实 MySQL 做了端到端验收。

## 高频问题

### 1. 为什么用 JPA？

业务以简单的单表查询、关联查询和分页为主，JPA 可以把表映射为对象，Repository 方法名能表达大部分查询，代码量少且适合当前规模。复杂报表可再用 JPQL 或原生 SQL。

### 2. Controller 和 Service 为什么分开？

Controller 负责 HTTP，Service 负责业务。这样业务方法可复用、可加事务、容易单元测试，也不会让一个 Controller 变得很长。

### 3. `@Transactional` 有什么用？

它保证方法中的多次数据库操作作为整体提交或回滚。例如删除文章时要先清多对多关系、再删评论、最后删文章；中间失败应整体回滚。

### 4. 如何避免重复增加阅读量？

用 Session 保存“用户 id + 文章 id”的阅读标记。同一 Session 首次访问执行数据库自增，之后刷新不再增加。

### 5. 为什么阅读量用更新语句而不是查出来再 `+1`？

数据库执行 `reading = reading + 1` 比“先查询、Java 加一、再保存”更能减少并发覆盖问题。

### 6. 如何实现数据隔离？

后台每次查询都带当前登录用户 id，例如 `findByAuthorId...`。修改和删除前还会再次校验记录所有者，不能只相信浏览器传来的 id。

### 7. 如何兼容 Django 密码？

解析 `pbkdf2_sha256$iterations$salt$hash`，读取每个密码自己的迭代次数，用 Java `PBKDF2WithHmacSHA256` 计算并做常量时间比较。注册时也生成同格式密码。

### 8. 为什么关闭 `open-in-view`？

避免模板渲染阶段悄悄查询数据库。需要关联数据时用 `@EntityGraph` 或在 Service 事务里明确加载，使 SQL 行为更可控。

### 9. 文件上传如何防止路径穿越？

服务端不采用客户端原文件名，而是生成 UUID；目录会去掉 `..`，最终规范化路径必须仍位于上传根目录内部。

### 10. 这个项目还有哪些生产化改进？

- 使用 Spring Security 和 CSRF 防护；
- 普通用户注册不应自动成为管理员；
- 密码迭代次数升级并支持登录后重哈希；
- 文件类型进行内容检测，不只检查扩展名；
- 接入日志、监控、数据库迁移工具 Flyway；
- 增加 Controller 集成测试和并发测试；
- 配置 HTTPS、反向代理和对象存储。
